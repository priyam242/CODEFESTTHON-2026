1. WHY GEMINI API SILENTLY FELL BACK ON RENDER (EXACT FORENSIC ROOT CAUSE)
================================================================================
During live user testing on Render, uploading a human selfie against a living room sofa
baseline resulted in:
"Under Model Tenancy Act (MTA) 2021 Sec 15: move-out inspection detected physical impairment on sofa and wall. Fair repair deduction assessed: ₹500"

Root Cause Identified & Verified with Live Telemetry:
1. API Key Format Rejection (HTTP 401):
   In the server environment, the configured key was:
   `AQ.Ab8RN6***[MASKED_ANTIGRAVITY_TOKEN]`
   When passed to Google's public Generative Language endpoint (`generativelanguage.googleapis.com`),
   Google strictly returned:
   ```json
   {
     "error": {
       "code": 401,
       "message": "API key not valid. Please pass a valid API key.",
       "status": "UNAUTHENTICATED",
       "details": [{
         "reason": "ACCESS_TOKEN_TYPE_UNSUPPORTED"
       }]
     }
   }
   ```
   An `AQ.` token is an Antigravity internal session token, whereas Google's public REST
   endpoint requires a genuine Google AI Studio Generative Language key (`AIzaSy...`).
2. Deprecated Model Aliases:
   Many projects in 2026 restrict older `gemini-1.5-flash` or `gemini-2.0-flash` calls.
3. Fallback Skin-Tone Blindness:
   The previous 16x16 fallback only checked average global RGB luminance. Because a warm
   human selfie against a neutral wall had an average RGB (~180) similar to a beige wall
   and tan sofa, global mean shift remained below the 80 threshold, allowing the selfie
   to slip into wear-and-tear heuristics!
