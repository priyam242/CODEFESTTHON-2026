1. EXECUTIVE OVERVIEW (सिस्टम का परिचय एवं उद्देश्य)
================================================================================
RentShield का पेमेंट सिस्टम भारत के Model Tenancy Act (MTA) 2021 के अनुरूप बनाया गया एक
द्वि-चरणीय (Two-Stage) क्रिप्टोग्राफिक साइबर-एस्क्रो पेमेंट इंजन है। यह किरायेदार (Tenant/Guest)
और मकान मालिक (Landlord/Owner) के बीच सिक्योरिटी डिपॉजिट के लेन-देन को सुरक्षित, पारदर्शी,
और विवाद-मुक्त बनाता है।

मुख्य विशेषताएं:
1. Dual Payment Channels:
   - Channel A: Direct UPI Dynamic QR Matrix (PhonePe, Google Pay, Paytm, BHIM) + Custom QR Image
   - Channel B: Razorpay Official Production Gateway (Credit/Debit Cards, UPI, Netbanking, Wallets)
2. 1-Click Instant UPI Confirmation:
   - पुराने 12-अंकों वाले बैंक UTR इनपुट बॉक्स को हटाकर एक-क्लिक कन्फर्मेशन बटन:
     "✅ I Have Paid on UPI App — Confirm & Close"
   - <300ms में ऑटो-क्लोज और रीयल-टाइम स्टेट रिफ्रेश।
3. Strict Role-Gated QR Isolation:
   - Tenant का QR कभी भी Owner के स्क्रीन पर डिपॉजिट मांगते समय नहीं दिखता।
   - Owner का QR कभी भी Move-Out रिफंड के समय Tenant के स्क्रीन पर नहीं आता।
4. Auto-Archival & Society Gate Pass NOC:
   - रिफंड सेटलमेंट होते ही प्रॉपर्टी एक्टिव वर्कस्पेस से हटकर बॉटम हिस्ट्री में चली जाती है।
   - एक्टिव डिपॉजिट का KPI मीटर तुरंत ₹0 पर क्लियर हो जाता है।
   - ऑफिशियल RWA Society Move-Out Gate Pass & No-Dues NOC जेनरेट होता है।

1. Separate Owner vs Guest QR Storage (Bug Fix):
   - पहले कोड में सिर्फ एक `customQrUrl` फील्ड थी, जिससे Owner का डिपॉजिट QR
     Move-Out रिफंड के समय Tenant के खाते पर दिखने लगता था।
   - हमने Prisma स्कीमा और डेटाबेस में दो स्पष्ट अलग कॉलम्स जोड़े:
     * `landlordQrUrl String?` (Owner का डिपॉजिट QR)
     * `tenantQrUrl String?`   (Guest का रिफंड QR)
     * `customQrUrl String?`   (बैकवर्ड कम्पैटिबिलिटी हेतु)
   - `PaymentModal.tsx` में Receiver QR का चयन इस प्रकार होता है:
     ```typescript
     const receiverQrImage = isLandlordPaying
       ? (tenancy.tenantQrUrl || (currentUserRole === 'TENANT' ? localQr : null))
       : (tenancy.landlordQrUrl || tenancy.customQrUrl || (currentUserRole === 'LANDLORD' ? localQr : null));
     ```

2. Zero Fake Fallback UPI IDs:
   - नए बनने वाले टेनेंसी रिकॉर्ड्स में कोई भी फर्जी UPI ID (`ramesh.malik@okhdfcbank`
     या `aarav@okaxis`) अपने आप प्री-फिल नहीं होती।
   - जब तक काउंटरपार्टी स्वयं अपना UPI ID या QR अपलोड नहीं करती, फ़ील्ड्स `null`
     रहती हैं और UI सुरक्षित वेटिंग स्टेट दिखाता है।
   - केवल प्री-सीडेड जज डेमो टेनेंसी (`demo-tenancy-indiranagar-001`) में टेस्टिंग
     के लिए वैलिड डेमो क्रेडेंशियल्स सुरक्षित रखे गए हैं।

3. Payer-Only Payment Gatekeeping:
   - `PaymentModal.tsx` के अंदर:
     ```typescript
     const isCurrentUserPayer = currentUserRole === (isLandlordPaying ? 'LANDLORD' : 'TENANT');
     const effectiveIsRecipientSettingsOnly = isRecipientSettingsOnly || !isCurrentUserPayer;
     ```
   - यदि कोई यूजर गलत रोल से मोडल खोलने का प्रयास करे, तो सिस्टम उसे तुरंत

CHANNEL 2: RAZORPAY PRODUCTION GATEWAY INTEGRATION
--------------------------------------------------------------------------------
- SDK लोडर:
  ```typescript
  export const loadRazorpayScript = (): Promise<boolean> => {
    return new Promise((resolve) => {
      if (typeof window === 'undefined') return resolve(false);
      if ((window as any).Razorpay) return resolve(true);
      const script = document.createElement('script');
      script.src = 'https://checkout.razorpay.com/v1/checkout.js';
      script.async = true;
      script.onload = () => resolve(true);
      script.onerror = () => resolve(false);
      document.body.appendChild(script);
    });
  };
  ```
- फ्लो:
  1. `paymentsApi.createOrder({ tenancyId, stage, amount })` सर्वर पर कॉल होता है।
  2. बैकएंड Razorpay Orders API (`https://api.razorpay.com/v1/orders`) से आर्डर
     आईडी (`order_xxx`) मंगाता है।
  3. फ्रंटएंड पर `window.Razorpay(options)` इंस्टैंशिएट होता है।
  4. पेमेंट सफल होने पर Razorpay कॉलबैक से `razorpay_order_id`, `razorpay_payment_id`,
     और `razorpay_signature` मिलते हैं।
  5. फ्रंटएंड इसे बैकएंड `/api/payments/verify` पर भेजता है जहाँ HMAC SHA-256
     हस्ताक्षर सत्यापित होता है:
     ```typescript
     const generatedSignature = crypto
       .createHmac('sha256', keySecret)
       .update(`${dto.razorpayOrderId}|${dto.razorpayPaymentId}`)
       .digest('hex');
     if (generatedSignature !== dto.razorpaySignature) {
       throw new BadRequestException('Razorpay signature verification failed.');
     }
     ```

B. PAYMENTS SERVICE METHODS (`server/src/payments/payments.service.ts`):
--------------------------------------------------------------------------------
1. `createOrder(dto: CreateOrderDto)`:
   - यदि Razorpay API Keys मौजूद हैं, तो लाइव आर्डर बनाता है।
   - यदि Keys नहीं हैं, तो फॉलबैक डायरेक्ट UPI मोड ऑन करता है।
2. `verifyPayment(dto: VerifyPaymentDto)`:
   - Branch 1 (Razorpay): HMAC SHA-256 सिग्नेचर चेक करता है।
   - Branch 2 (Direct UPI Scan): `pay_RS_DIRECT_UPI_${Date.now()}` जारी करता है।
   - Branch 3 (UTR Input): 12-अंकों का UTR वैलिडेट करता है।
   - Tenancy State Update:
     * यदि `stage === 'DEPOSIT'`: `depositPaid = true`, `depositPaymentId = verifiedId`
     * यदि `stage === 'SETTLEMENT'`: `status = 'SETTLED'`, `settlementPaymentId = verifiedId`,
       `settledAt = new Date()`
3. `updateRecipientUpi(dto)`:
   - काउंटरपार्टी को अपना UPI VPA या कस्टम QR इमेज अलग-अलग सुरक्षित करने की अनुमति देता है।
